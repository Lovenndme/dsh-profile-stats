## 0. 你的角色

你是一位资深前端 + 数据可视化设计师。目标是把一个已经能用、但视觉平庸的插件面板，重做成一个**真正好看、信息层级清晰、读得懂**的产品级界面。

**明确允许你抛弃现有视觉方案**：现在的配色、间距、卡片样式、图表形态、动效都可以全部推翻，不需要"兼容旧风格"。唯一的边界是下面第 2 节列的硬约束。

## 1. 项目是什么

DeepSeek Harness（下称 DSH）是一个本地 AI Agent 桌面应用。插件系统允许第三方插件往界面上"插一块"。

本插件 `dsh-profile-stats` 给它加一个**个人用量主页**：从本机会话日志里统计 token 用量，画成图表，让用户看清"钱花在哪了"。

- 仓库根目录：`dsh-profile-stats/`（当前就在你的工作目录下）
- 你会改的文件：**`client.js`**（浏览器半区，单文件，约 2400 行，含全部组件 + CSS 字符串 + 中英文案）
- 不要改：`index.js`（宿主半区，负责读日志和聚合）、`package.json`、`cordis.patch.yml`

### 插件在界面里的位置

- 左侧竖排图标栏（`sidebar.panellist`）里有一个「个人主页」入口
- 点开后，右侧主区（`main` slot，key=`profile`）渲染整页
- 主区可用宽度约 1180px，窗口变窄时会更窄（最小到 ~700px 也要能用）

### 技术形态（必须保持）

`client.js` 必须保持这个外壳，只替换里面的组件：

```js
window.__ModuleLoader__.load({
  id: 'dsh-profile-stats',
  factory(require) {
    const React = require('react')
    const h = React.createElement
    // ...你的所有组件与样式...
    return { inject: ['slots'], apply }
  },
})
```

- `apply(ctx)` 里用 `ctx.get('slots')` 注册两个 slot（`sidebar.panellist` → 入口按钮，`main` → 页面）
- React 由宿主以 `require('react')` 提供，**不能** `import` 任何包、不能用 npm 依赖、不能用 CDN、不能用 webfont
- 图标一律内联 SVG（`currentColor` 描边）
- 图表自己用 SVG / CSS 画，**不引入图表库**

## 2. 硬约束（违反即不合格）

1. **只读一个接口，绝不重算统计**
   数据全部来自 `GET /api/dsh-profile-stats/snapshot`。你只做"画"和"派生展示值"（百分比、平均值、分桶求和）。不要重新定义"什么算 token"。

2. **不改数据契约**：不要为了界面好看去改 `index.js` 或要求宿主多返回字段。需要的派生值自己在浏览器半区算。

3. **颜色必须走主题 token**，不能写死十六进制。应用有**浅色和深色两套主题**，写死颜色必然在其中一套里瞎掉。可用：

   ```
   --dsw-alias-bg-base, --dsw-alias-bg-layer-1, --dsw-alias-bg-layer-2, --dsw-alias-bg-overlay
   --dsw-alias-border-l1, --dsw-alias-border-l2
   --dsw-alias-label-primary, --dsw-alias-label-secondary
   --dsw-alias-brand-primary
   --dsw-alias-state-success-primary, --dsw-alias-state-warn-primary,
   --dsw-alias-state-error-primary, --dsw-alias-state-idle-primary
   ```
   （需要透明度/混合时用 `color-mix(in srgb, var(--dsw-alias-brand-primary) 55%, transparent)` 这类写法）

4. **界面里不加解释性说明文字**。这是主人的硬性偏好：UI 只呈现**数据与控件**。不要写"口径说明""提示：…""此图表示…"这类小字。需要解释的东西写进 README，不进界面。（数据自己的标签、单位、坐标轴刻度、tooltip 当然要，那不叫说明文字。）

5. **零外部请求**。除了这三个同源路由，不要 fetch 任何地址：
   - `GET /api/dsh-profile-stats/snapshot`（读数据）
   - `POST /api/dsh-profile-stats/refresh`（点刷新按钮时）
   - `POST /api/dsh-profile-stats/update`（点更新按钮时，仅在有新版本时出现）

6. **无障碍**：所有交互元素键盘可达（Tab 顺序合理、有 `:focus-visible` 样式）；动效必须尊重 `@media (prefers-reduced-motion: reduce)`。

7. **不崩、不空白**：任何数据为空/为 0 的情况下，页面要能看，不能抛错、不能让整块消失（见验收第 3 节）。

## 3. 必须保留的功能清单（验收逐条核对）

以下功能**一个都不能少**，但呈现方式你完全自由（可以合并、可以换图表类型、可以换布局）。

### 3.1 页头
- 头像（首字母或 `identity.avatar`）、用户名、`@handle`
- 刷新按钮（触发 `POST /refresh`，重新拉快照）
- 有新版本时出现「更新到 x.y.z」按钮（触发 `POST /update`）

### 3.2 五个核心指标卡
| 指标 | 来源 |
|---|---|
| 累计 Token 数 | `totals.tokens` |
| 今日 Token 用量 | 今日那天的 `daily[].tokens` |
| 最长任务用时 | `totals.longestTurnMs` |
| 最长连续天数 | `totals.longestStreak` |
| 当前连续天数 | `totals.currentStreak` |

### 3.3 Token 活动（日历热力图）
- 近 12 个月，日格热力图
- 三档口径切换：**每天 / 每周 / 累计总量**（切换后**图形或颜色必须有肉眼可见的差别**，这是之前踩过的坑：三档都渲染同样 365 格、只改颜色深浅，压缩格子后完全看不出变化，等于把功能做没了）
- 悬浮显示"日期 + 用量"
- 悬浮浮层应跟随鼠标或至少不被视口裁切

### 3.4 模型分布
- **自带「按日 / 按周 / 按月」三档**，窗口各 12 个桶（日=近12天、周=近12周、月=近12个月）
- **这一块必须独立，不受其他控件影响**
- 图形式：按模型家族堆叠（前 6 个家族各自一段，其余合成「其他模型 (N)」一段）
- 图例：每个家族给**自己的用量**；卡片头部给**总计**
- 纵轴：整齐刻度（1/2/2.5/5 × 10ⁿ），单位自动在 万/亿 之间选
- 悬浮：该桶的日期 + 各段用量
- 空数据时保留卡片，不消失

### 3.5 Token 构成（Cache Lens）
- 顶部两个大数字：
  - **总 Token**（`totals.tokens`）
  - **缓存命中率** = `cacheRead+cacheWrite` ÷ (`cacheRead+cacheWrite` + **未缓存输入**)
    - 注意：未缓存输入必须用 `总Token − 缓存 − 输出` 反推，**不能**直接用 `totals.inputTokens`（不同供应商的 `inputTokens` 语义不一致，实测会多算 1.6%）
- 一条横向分段占比条，三段：**缓存命中 / 未缓存输入 / 输出**，宽度 = 各段占**总量**的比例，合计 100%
- 三行明细：色块 + 名称 + 用量 + 占**总量**的百分比
- 「放大非缓存细分」按钮 → 切到以**非缓存合计**为分母的视图（只含 未缓存输入 / 输出），并明示分母变了；可「返回整体构成」
- 悬浮：类型 + 用量 + 占比
- 段宽不得夸大极小的类别（可以给最小可见宽度或用其他非误导方式标记），但**不能因为"要能点"就把 0.2% 画成 20%**

### 3.6 供应商分类
- **自带「今日 / 累计」两档，独立于其他控件**
- 每行：供应商名（可读名称，不是原始 id）+ 用量 + 占比 + 进度条
- 空数据时保留卡片

### 3.7 状态与异常
- 首次扫描中：显示进度（`progress.done / progress.total`），不要显示一堆 0
- 完全无会话：显示空状态，不是白屏
- 接口失败：显示错误态 + 重试

## 4. 数据契约（不用去读宿主代码，照这个写）

`GET /api/dsh-profile-stats/snapshot` 返回：

```jsonc
{
  "identity": { "name": "Mike", "handle": "@lovenndme", "avatar": "M" },   // avatar 可缺省
  "totals": {
    "tokens": 3330000000,            // 本机日志折叠出的总 token（已去重继承前缀）
    "calls": 12345,                  // 模型调用次数
    "inputTokens": 75000000,         // 注意语义不一致，见 3.5
    "outputTokens": 6900000,
    "cacheReadTokens": 3200000000,
    "cacheWriteTokens": 0,           // 可能为 0
    "sessions": 69,
    "activeDays": 48,
    "firstDay": "2026-08-17",
    "lastDay": "2026-11-04",
    "peakDay": { "date": "2026-10-26", "tokens": 1200000000 },
    "peakStepTokens": 0, "peakStepSession": null,
    "peakSessionTokens": 0, "peakSession": null,
    "longestTurnMs": 3700000,        // 毫秒
    "longestTurnSession": "…",
    "longestStreak": 10,             // 天
    "currentStreak": 10,             // 天
    "tokensWithInherited": 3400000000
  },
  "daily": [
    {
      "date": "2026-11-04",          // 本地日期 YYYY-MM-DD，只包含有活动的天
      "tokens": 16500000,
      "calls": 42,
      "inputTokens": 300000,
      "outputTokens": 41000,
      "cacheTokens": 16000000,       // 当天缓存（read+write）
      "byProvider": { "myapi": 16500000, "wincode": 0 },
      "byModel":    { "deepseek-v4-1-flash": 16500000 }
    }
  ],
  "scanning": false,
  "progress": { "done": 69, "total": 69 },
  "generatedAt": 1762350000000,      // 毫秒时间戳
  "update": { "available": false, "latest": "2.4.11", "installed": "2.4.11" }  // 可缺省
}
```

补充事实：
- `daily` **可能不含某天**（那天空白是正常的，不是 bug）
- `byModel` 的键是**模型家族**（形如 `deepseek-v4-1-flash` / `deepseek-v4-pro` / 其他厂商 id）。展示名建议做成 `DeepSeek V4.1 Flash` 这类可读形式
- `byProvider` 的键是渠道 id（`myapi` / `wincode` / `arkcli-coding-plan` / `deepseek-official` …），展示时映射成可读名，未知的 id 原样显示
- 数值单位建议：≥1e8 用「亿」，≥1e4 用「万」，保留 1 位小数；**计算过程中一律用原始整数，只在渲染那一步格式化**

## 6. 自主探索：找出并修掉没人事先告诉你的问题

除了重做 UI，你还有**第二个任务**：把 `client.js`（必要时连同 `index.js`）当成一份陌生的代码去审，主动找出 bug、逻辑不合理、边界漏洞、死代码、性能问题。**发现问题你有权直接修**，不必逐条等我确认。

### 6.1 重点审查方向（不限于此）

- **统计口径**：同一份数据在不同区块里算出不同结果；百分比分母前后不一致；把 `inputTokens` 当"未缓存输入"用（已知会多算约 1.6%）
- **取整与精度**：计算链路里出现 `Math.round` / `toFixed` 导致下游用舍入值继续算；大数相加后显示误差
- **空态与边界**：0 数据、只有一条数据、未来日期、跨月/跨年、时区（本地日期 vs UTC）、字典序比较日期
- **分桶完整性**：日/周/月分桶是否漏掉"没有活动的桶"、周起点是否正确、月末跨月是否错位
- **状态机**：`scanning` 期间刷新、连续点刷新、请求失败后重试、`update` 按钮在重装期间的行为
- **组件生命周期**：stale closure、`useEffect` 依赖、定时器未清理、重复渲染导致动画重播
- **DOM/样式**：类名漂移、重复 id、`z-index` 打架、浮层被 `overflow` 裁切、窄窗口溢出
- **可访问性**：只能鼠标操作的交互、无 `focus-visible`、`aria-label` 缺失
- **死代码**：写了但永不成立的分支、导出未使用的函数、注释与实现不符

### 6.2 分级（决定你怎么处理）

| 级别 | 定义 | 处理方式 |
|---|---|---|
| **A** | 数据算错、崩溃、空白页、**误导性展示**（用户会据此做判断） | **必须修**，并加回归断言 |
| **B** | 体验/性能/可维护性问题（卡顿、重复渲染、死代码、命名不符） | 建议修，改动小的直接修 |
| **C** | 涉及统计口径或产品决策（"该不该这样定义"） | **只报告，不改**，写出两种口径的差异等我定 |

### 6.3 不许静默改口径

任何会**改变用户看到数字**的修改，必须在报告里单列，并写清：

- 改之前显示什么、改之后显示什么
- 哪个是对的、依据是什么
- 同一份数据下，**哪些区块的数字会跟着变**

如果说不清"改了之后为什么更对"，就不要改，标成 C 类交给我。

### 6.4 修复纪律

- 每修一个 A 类问题，配一条断言（在重写后的 `client-smoke.mjs` 里）
- 一个 commit 只做一件事，便于单独回退
- 修 UI 与修逻辑尽量分在不同 commit
- 遇到"需要改宿主 `index.js` 才能修"的问题：**不要改**，写进报告（宿主改动会牵动缓存版本与重扫，必须由我决定）
